# 项目理解报告

## 1. 图像生命周期与所有权

frame.image = buffer_ 是浅拷贝，共享底层像素内存，下次读图覆盖 buffer_（copyTo 复用了这块内存）会把旧帧的数据也篡改掉，导致校验和对不上。改成 buffer_.clone()做深拷贝后，每个 Frame 都有独立的像素数据，后续刷新不会受影响

## 2. 并发处理与恰好一次

队列内部有互斥锁保护，用`pop` 取出数据的同时会将其移出队列，所以同一帧只会被一个 worker拿到，不会重复处理。producer 读完后用 `close()` 唤醒所有正在等待的 worker，worker 会继续把队列里剩余的帧使用完，到队列空了才退出，既不重复也不丢帧

## 3. 共享统计数据

producer 和多个 worker 负责累加，主线程最后读快照。原版的计数器是 int，多线程同时累加会产生写入覆盖。在统计模块里加了 mutex，累加和读快照时用 lock_guard 加锁，避免冲突，保证读取到的数据准确一致

## 4. 线程关闭协议

退出主要靠 wait()（显式调用，或者在析构时自动调用）依次 join 生产者和各个 worker，等到把任务全跑完再结束。析构函数里加上 wait() 防止用户忘记调用导致崩溃。每次 join前都加了 joinable() 检查，避免重复 join 报错
